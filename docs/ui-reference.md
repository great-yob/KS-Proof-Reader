## UI flow (v5) — 단일 워크스페이스 셸

[ui/main_window.py](../ui/main_window.py) is a **persistent single-workspace shell**, not a wizard. The root layout is **horizontal**: a full-height left `Sidebar` ([ui/widgets/sidebar.py](../ui/widgets/sidebar.py) — brand wordmark on top + embedded `StepperRail` nav + `© kim daekyung`/version footer at the bottom) and, to its right, a **main column** holding `AppHeader` (top — a **custom title bar**: account chip (login / account menu: 비밀번호 변경·사용자 관리·로그아웃) + curator button (curators only) on the left, theme toggle + window minimize/maximize/close on the right; the logo lives in the sidebar; 새 분석 is the footer's 초기화) / center row (`stage` + `ActivityPanel`) / `StatusFooter` (bottom). The window is **frameless** (`Qt.FramelessWindowHint`, no native title bar); `MainWindow.nativeEvent` handles Win32 `WM_NCHITTEST` to give edge-resize on all sides and turns the top `_DRAG_ZONE_H` strip (minus interactive buttons) into the move/snap region via `HTCAPTION`. The header and footer are therefore confined to the main column (separated from the sidebar). `StepperRail` exposes the 4 macro steps 설정/분석/검토/완료 with per-step result subtitles; built with `embedded=True` it drops its own width/chrome so the sidebar owns the background+border. `MainWindow.rail` is an alias for `sidebar.rail` so existing call sites are unchanged. Regions are built once and never destroyed; only the center `QStackedWidget` (`stage`) swaps among four panels in `ui/widgets/`: `SetupPanel` (upload+options merged) / `RunningPanel` / `ReviewPanel` / `ResultPanel`. `_show_phase()` keeps rail/footer/stage in sync; review is skipped when `options["auto_apply"]` is true (confidence=="low" auto-rejected). Two QThread workers (`ProofreadingWorker`, `ApplyWorker`) are owned by the window; their signals fan out to the persistent components. `_cleanup_worker` requests stop and waits up to 5s before discarding — keep that pattern when adding new workers.

## 설정 화면

⚠ 설정 화면의 결과물 카드는 값이 다섯이 되어 **2칸 × 3줄**이다(홀수라 마지막 줄 빈 칸은 stretch로 채운다 — 안 채우면 남은 카드가 줄 폭 전체로 늘어난다). 줄이 하나 늘어난 만큼 `setup_panel`의 세로 여백 상수 6개를 한 번 더 조였다(`_CARD_PAD_V` 9 · `_ROW_PAD_V` 8 · `_SEC_GAP` 9 · `_SEC_SPACING` 20 · `_MAIN_PAD_V` 14 · `_ROW_GAP` 10 — 현재 값, 정본은 코드 상수) — 기본 창(1500×900)에서 세로 스크롤이 사라지는 것을 실측했다(`_SEC_SPACING` 16 시점 내용 666px / 뷰포트 758px; 그 뒤 20으로 되돌림). ⚠ 가로 여백은 여전히 건드리지 말 것.

**설정 화면의 우측 칸은 첨부 2단이다** (`AttachPanel`, 2026-09-03): 위 `FilePanel`(한글 원고) : 아래 `DictPanel`(사용자 사전 엑셀) = **2 : 1 높이**. `MainWindow.file_panel`은 `attach_panel`의 별칭이라 `set_file`/`has_file` 호출부는 그대로다. ⚠ 세로 2:1은 `stretch(2,1)`만으로 정해지지 않는다 — QVBoxLayout은 stretch를 나누기 전에 각 칸의 최소 높이를 먼저 확보하므로, 좌우 1:1에서 겪은 것과 **같은 함정**이다(memory `setup-panel-equal-grid-qt-traps`). 두 칸 모두 세로 정책 `Ignored`로 최소 높이를 0 취급시켜 비율이 오직 stretch로 정해지게 한다. ⚠ 그래서 `DictPanel`은 `FilePanel`의 축소판이 아니라 **여백·아이콘을 따로 잡은 낮은 칸**이다(1/3 높이에 드롭존 기본값을 그대로 쓰면 내용이 잘린다). 첨부 직후 파일명 옆의 '등록 용어 N건'은 `DictPanel._peek`이 같은 로더로 한 번 읽어 보여 주는 **표시용**이다 — 실제 교정에 쓰는 값은 언제나 워커가 분석 시작 시점에 다시 읽는다(그 사이에 사용자가 엑셀을 고칠 수 있다).

## 활동 로그 (Activity log)

**Activity log** ([ui/widgets/activity_panel.py](../ui/widgets/activity_panel.py)): the right-hand log **does not print worker messages verbatim**. Pipeline logs are written as evidence — long sentences carrying the *reason* for each decision, interleaved with COM-bridge plumbing, per-chunk progress and boilerplate — which in a ~300px column reads as a wall of text (user report 2026-07-23). A display layer therefore ① hides low-value rows (`_DROP`, `_ITEM_RE`), ② rewrites each line to keywords via an ordered regex table (`_RULES` — reason clauses dropped, **counts always preserved**), and ③ collapses repeated progress lines onto one self-updating row via a coalesce key (`AI 분석 n/m 청크`). `err`-level lines bypass all three (tracebacks must survive intact). ⚠ **Screen-log convention, binding on every log line you add (user directive 2026-07-31)**: a displayed line carries a `[태그]` prefix and an `n건` count — **never a concrete example** ('원문' → '교정' word lists). Per-item detail belongs in the raw log only, emitted as an indented `      · …` bullet: `_ITEM_RE` drops *any* bullet-led line by shape, so no per-phrase `_DROP` entry is needed (the previous per-phrase list is what let `· 상호 무효화 쌍 → 사용자 결정 '…' ↔ '…'` leak onto the screen — an unregistered phrase is one `log()` call away from becoming a visible row). Corollary: **summary lines must not start with `·`** — use `→` or `[태그]`, or the count disappears. The sweep that proves it is `_condense`-over-every-`log()`-literal; both invariants (every displayed line tagged / no manuscript examples) currently hold at 154 literals. ⚠ `self._entries` keeps the **raw** messages — `get_proofreading_log()` and post-hoc debugging depend on them, and the result dashboard runs its own separate curation; condensing only ever happens on screen. Rendering is a **2-column `QTextTable`** (time | content) built incrementally: a wrapped message stays inside its own cell instead of flowing under the timestamp, which is what the old single-block `시각&nbsp;&nbsp;내용` layout did. `_write_row` rewrites a row's cells in place (used by both append and coalesce); `refresh_theme()` rebuilds the table from `_rows` (already-condensed), never from `_entries`. The panel has **no summary chips** — they duplicated the footer/rail counters and were removed 2026-07-23 along with `set_detected`/`set_summary`.

## 디자인 시스템 · 툴팁

**Design system**: [ui/styles/theme.py](../ui/styles/theme.py) holds the `LIGHT`/`DARK` token palettes, `current_palette()`/`current_mode()`, and `build_qss(palette)` (sizes are literal px in the QSS — there is no scale-token table). Style **only** via global QSS objectName/property selectors (e.g. `variant="primary"`, `role="card"`, `state="active"`) + `restyle(widget)` after a property change — avoid per-instance `setStyleSheet` in persistent widgets so dark-mode toggle reskins everything via `apply_theme(app, mode)`. Directly-painted/HTML widgets (`ToggleSwitch`, review `QTextBrowser`, icons, activity log) implement `refresh_theme()`; `MainWindow._refresh_all_themes()` walks the tree and calls it on every descendant after a toggle. Reuse primitives from [ui/widgets/components.py](../ui/widgets/components.py) (`make_button`, `card`, `section_card`, `badge`, `chip`, `label`). Theme mode persists via `ConfigLoader.get_theme()/set_theme()` ([APP] section). ⚠ **Tooltips are a theme-independent dark chip** (`tooltip_bg`/`tooltip_fg`/`tooltip_border`, identical in both palettes — the same "theme-independent surface" idiom as `LightConfirmDialog` and the toast). Keep the text light and do **not** split those tokens per theme; `apply_theme` also mirrors them into `QPalette.ToolTipBase/ToolTipText` (tooltip-only roles — widening that palette write would repaint native widgets the QSS doesn't cover). The rule body lives once in `_TOOLTIP_RULE`, used by both the global QSS and `tooltip_qss()`.
★**A selector-less instance stylesheet cascades into the tooltip and beats the global `QToolTip` rule** — Qt wraps `w.setStyleSheet("background: transparent;")` in `* { … }`, and QTipLabel counts as part of that subtree. Every tooltip bug seen here is that one cause wearing different faces (measured 2026-08-12 by real screen capture): review cards (`_inner_card` = `background:#FFFFFF`) rendered **white-on-white in light mode**; the result panel (`_twidget`/`_Riser` = `background:transparent`) rendered **pure black** — which is what the earlier "this environment's Qt paints tooltips black no matter what the stylesheet says" note actually measured. That note was wrong: with no selector-less ancestor, forcing `background-color:#FF0000` renders **red**. Dark mode hides the bug because the ancestor's surface color is already near-black. The fix is `theme.local_qss(decls)`: it states the `*` selector explicitly (identical to what Qt does — verified pixel-for-pixel, 0 differing pixels in both themes) and re-declares the `QToolTip` chip after it, so the type selector out-specifies `*`. **Use it for any new declaration-only stylesheet on a container**, and never mix declarations and rules in one string (Qt fails to parse and re-wraps the whole thing in `*{…}`). ⚠ Verify tooltips by **real screen capture** (`QScreen.grabWindow(0)` cropped to the QTipLabel's geometry × devicePixelRatio) — `widget.grab()` returns the stylesheet's intent and shows nothing wrong.

## 번들 자산 (assets/)

**Bundled assets** (under `assets/`, resolved by [ui/styles/assets.py](../ui/styles/assets.py) for dev + frozen): `assets/fonts/` Pretendard **TTF** (the `static/alternative` TrueType-hinted build — OTF/CFF rendered blurry & vertically clipped on Windows/Qt; loaded by [ui/styles/fonts.py](../ui/styles/fonts.py) `load_fonts()` in `main.py`; primary UI font, set via single-family `font-family: "Pretendard"` since Qt QSS ignores comma fallback lists; the app font uses `QFont.PreferNoHinting` because Windows' default hinting grid-snaps and drops thin top strokes e.g. ㅎ), `assets/icons/` Lucide SVGs (ISC) rendered/recolored to QIcon/QPixmap by [ui/styles/icons.py](../ui/styles/icons.py) — use `IconButton`/`IconLabel` or `make_button(..., icon="name")`, never emoji glyphs. **Build note**: PyInstaller must bundle `assets/` and the `PySide6.QtSvg` + `qsvg` image-format plugin. `assets/icons/` holds only icons the code references (unused ones were pruned 2026-10-18) — add a Lucide SVG when you need a new name. ⚠ **`assets.base_dir()` must resolve to `sys._MEIPASS`, not the EXE folder** — PyInstaller onedir puts `--add-data assets;assets` inside `_internal/`, and the old EXE-folder-only rule made every icon, the brand logo, and **Pretendard itself** vanish from the released build with no error at all (a missing SVG becomes an empty pixmap; a missing font silently falls back). This is the *opposite* of the data rule in `datapaths.py` — dictionaries live beside the EXE precisely so they can be replaced independently, while assets are code-coupled and belong in the bundle. `build_dist.verify()` now fails the build if `_internal/assets/{icons,fonts,logo}` is missing or empty.

## 검토 화면 (Review panel)

**Review panel** ([ui/widgets/review_panel.py](../ui/widgets/review_panel.py)): cards are **per-occurrence** — a word repeated N times in the manuscript yields N cards (each tagged `반복 k/N`), ordered by document position; clicking a card scrolls the preview to that occurrence (`<a name>` anchors + `scrollToAnchor`). Cards default to **pending** (white); each occurrence has its own accept/reject (split ✓/✕ solid icon buttons, card tinted green/red by `status` property). **반복 일괄 처리**: a user's accept/reject on any card auto-propagates to the group's other untouched repeat cards (`occ["auto"]`); flipping an auto-set card to the opposite raises a confirm popup and, if confirmed, flips **only that card** (`occ["by_user"]` — never overwritten by later propagation). **용어 일관성 통일** (`_unify_dialog`): 띄어쓰기 일관성 카드(marked `Correction.consistency_flip` — set **only** by worker [7] `find_compound_spacing_consistency` consumption; `consistency_pass` variants explicitly unset it; never enable for norm corrections) is **not** a per-item verdict but a document-wide 표기 choice, so `_set_status` routes it to `_unify_dialog` **before** the repeat/auto branch. ★Accept (unify to the card's corrected form) applies **immediately with a toast, no popup** (user decision 2026-10-19 — the result is already printed on the card); reject (unify to the original form, which rewrites the majority occurrences) shows a popup listing every form that changes and how many places (`_unify_plan`). Both run one operation, `_apply_unify(c, target)`, at **word** level: every unify card of the same word (spaces removed — `_unify_members`; junction-group cards excluded, the junction pass groups siblings together) is decided at once — cards whose original is the target are rejected, the rest get `corrected = target` and are accepted (restored to their first proposal/reason from `_unify_base` when the target returns to it), and a form with no card yet (e.g. the old majority) gets a synthesized `form → target` card, never a second card for an original that already has one (two cards with one original shadow each other — the 3-variant bug of 2026-10-19: rejecting the 2nd sibling used to create a duplicate-original reverse card whose occurrences were all shadowed, silently leaving a mix). Symmetric — picking on any card of the word moves the whole word to that form; no reverse card is ever synthesized for non-`consistency_flip` cards (that would de-standardize norm corrections). All cards stay visible (user decision 2026-10-19: every card is shown to the proofreader — collapsing occurrence cards was rejected). Consequence: consistency cards have **no per-occurrence partial** accept/reject. The old "반대 표기로 통일" link button was removed 2026-07-21 (users rejected without noticing it, leaving both 표기 mixed). Both paths preserve other cards' per-occurrence states by re-running only sort/`_mark_stem_boundary_skips`/`_resolve_overlaps`/`_derive_all` (**never** rebuild occurrences — that wipes partial decisions), and both are dispatched via `QTimer.singleShot(0, …)` after the popup closes ⚠ **and neither rebuilds the card list** (2026-07-27 perf fix): the old code called `_rebuild_cards()` and then synchronously re-created every card from index 0 up to the acted-on one, so the delay scaled with the card's position in the list (measured 0.8s at card #20 → **6.2s at #690**). Unify only changes ① two groups' statuses and ② — on the reject direction, and only when the reverse correction is synthesized fresh — a few new occurrences. So status-only paths just call `_restyle_dirty()` (repaints solely the cards whose `(status, is_active)` actually changed, tracked in `card._styled`), and `_apply_unify` returns `grew=True` only when occurrences were added, which is the sole case that runs `_sync_cards()` (remove-then-insert diff against the live card list) plus the anchor restore. What makes this possible is that **occurrence identity is a stable `uid`, not a list index** (`_new_uid`/`_occ_pos`/`_reindex_occ`): card `occ_id`, preview anchors `c{uid}` and `_active_occ_id` all key off it, so re-sorting `_occ` when reverse occurrences join no longer desynchronizes every card — which is exactly why a full rebuild used to be the only option. Same release: `_mark_stem_boundary_skips` memoizes per occurrence (`_stem_done`, invalidated by `_on_corrected_edited`), `_resolve_overlaps`/`_render_with_text` use the `_Occupancy` bytemap instead of an O(occurrences²) interval scan, `_derive_all` groups in one pass, and `_refresh_preview(defer=True)` coalesces re-renders on an 80ms timer — 96% of preview cost is Qt's `setHtml`, not the Python render (455ms of 475ms at 3,830 occurrences), so rapid accept/reject clicks now cost one re-typeset instead of N. `load()` and `refresh_theme()` stay synchronous (dialog teardown first, else a ghost white window; `_set_status` must `return` immediately since `_rebuild_cards` deletes the card widget it was passed). The popup is `LightConfirmDialog` — a frameless **always-light** modal built on `build_light_card()`/`LIGHT_CARD_QSS`, the same surface the **toast** (`_toast`, 반복 일괄 처리·용어 일관성 통일 알림) uses, so both read as one system. ★Toasts use **three slots (top · middle · bottom) in rotation** (user decision 2026-10-19): the n-th toast takes slot n mod 3, each has its own 4.5 s timer, and `_position_toasts` spaces the visible ones by the tallest height so they never overlap — with a single centered toast, a second one hid the first before it timed out (it became frequent once consistency-card accepts switched from a popup to a toast): head title + divider + body, drawn in-widget so the OS dark title bar can't leak in, every visual property re-declared under `#lcd*` objectName selectors to beat the global dark QSS, and wordWrap labels given a measured `setMinimumWidth` (their sizeHint collapses to ~230px and folds a one-liner into 3 lines). Both are theme-independent — do **not** add `refresh_theme()` to them. **Card list loading is measured-tuned** (constants at the top of `ReviewPanel`): a 50-card batch cost ~433ms of frozen UI, and since each batch carries a ~30ms whole-list layout pass, smaller batches only multiply the total — so the fix isn't batch size. Instead: first batch `_INITIAL_CARDS` (screen-filling only), the rest by an **idle prefetch timer** that runs only after `_IDLE_QUIET_MS` of no interaction (`_note_interaction()` is called from scroll/accept-reject/`_scroll_to`) and **parks itself once `_PREFETCH_AHEAD` viewports of cards are buffered below the fold** — never preload everything, because insert cost scales with how many cards are already alive. `_on_scroll` keeps an 80% safety net (`_SCROLL_CHUNK`). `_rebuild_cards` swaps the whole scroll content (`_new_scroll_content`) instead of detaching cards one by one (309ms → 64ms for 200 cards, and no widget ever becomes a top-level window, which also retires the old ghost-window workaround) — ⚠ `QScrollArea.setWidget()` destroys the old widget **synchronously**, so clear `self._cards` first. Never call `_emit_counts()` from `_load_more_cards`: counts derive from `_occ`, not from loaded cards. ⚠ **A freshly created card's `pos()` is not final for several layout passes** (measured y: 0 → 877 → 2953); reading it after a single `singleShot(0)` lands mid-settle and scrolls to the wrong place, and forcing `activate()`/`adjustSize()` does not fix it. `_scroll_to` therefore goes through `_place_card(occ, offset, smooth)`, which re-measures until the position stops changing. Before adding an action that changes the card list, ask whether it needs a rebuild at all: status-only → `_restyle_dirty()`; occurrences added → `_sync_cards()`; only a change of list composition (filter, theme) → `_rebuild_cards()`. Every card action ends with `_scroll_to` (unify included — 2026-07-27). ⚠ The old `_capture_card_anchor`/`_restore_card_anchor` pair and `_do_unify`'s synchronous load + `setUpdatesEnabled(False)` guard were **deleted** 2026-07-27 once unify stopped rebuilding — do not reintroduce them. Likewise `_refresh_preview(keep_scroll=True)` is the default because `setHtml` resets QTextBrowser scroll to 0 — accepting one card used to fling the 원문/교정문 panes back to the top; only `load()` passes `keep_scroll=False`. It suspends `_scroll_sync` around the swap and restores each scrollbar twice (immediately + next tick, since the document's scroll range isn't final until it has laid out). To make the previews *follow* an action instead, call `_scroll_previews_to(cid)` (previews only — leaves the card list where it is) from a `QTimer.singleShot(0)` so it runs **after** that restore; `_do_unify` does this to match what `_scroll_to` gives normal cards, and passes `active_occ=` into `_apply_unify` so `_mark_active_occ` can re-resolve the occurrence index after the re-sort without a second render. ⚠ the panel's correction list is a sorted **copy**, so `main_window._start_apply` re-syncs `self._corrections = review_panel.get_corrections()` before applying — without it panel-added reverse corrections never reach ApplyWorker/errata. **Partial reject is real**: `_derive()` sets the unique `Correction.status` (accepted if any occurrence accepted) and `skip_occurrences` = occurrence indices (document order, 0-based) NOT accepted; this flows `apply_worker` → `HwpEditor.apply_corrections` → bridge `apply()`, whose `RepeatFind` loop skips those `count` indices (and disables the AllReplace fallback when a skip set is present). `counts_changed`/`get_counts()` report **occurrence-level** counts. **Card width is fixed to the column** (no h-scrollbar): the 원본 label gets ZWSP soft-break points (`_soft_breakable`, default size policy — a custom `Ignored` policy broke heightForWidth), the 교정 field is a `GrowingTextEdit` (wrap-anywhere QTextEdit that grows vertically, `QLineEdit`-compatible `text()`/`editingFinished`; height = doc height + measured chrome, **never** `frameWidth()` which lies under QSS borders), and cards are vertically `Maximum` so leftover list space goes to the trailing stretch, not into the cards.

## 검토 저장 · 이어서 하기 · 다시 적용 (2026-10-23)

사용자 요구 세 가지를 한 구조로 푼다: ① 결과물을 만든 뒤 검토로 돌아가 결정을 바꾸면 **다시 적용**할 수 있어야 한다 ② 분석이 끝난 뒤 앱이 꺼져도 Gemini를 다시 부르지 않아야 한다 ③ 검토 도중 초기화하고 다른 원고를 먼저 해도 진행분이 남아야 한다.

- **자동 저장** — [core/review_session.py](../core/review_session.py). 분석이 끝나는 순간(`_on_analysis_done` 끝, 로그까지 쌓인 뒤 — 전자동 모드는 적용 직전) 원고별 저장본을 만들고, 이후 `counts_changed`마다 1.5초 디바운스로 다시 쓴다. 적용 완료·초기화·종료 때는 즉시 쓴다(`_flush_session_save`). 사용자가 누를 '저장' 버튼은 없다 — 강제 종료에서도 살아야 하므로.
- **원고 식별 = 파일 내용의 SHA-256**(앞 32자). 경로가 바뀌어도 같은 원고, 한 글자라도 고치면 다른 원고다(등장 좌표가 추출 텍스트에 묶여 있다). 원고 하나에 저장본 하나 — 새로 분석하면 같은 자리에 덮어쓴다.
- **저장 위치** `datapaths.cache_dir()/review_sessions/`(`<sid>.json.gz` 본문 + `<sid>.meta.json` 요약). ⚠ **원고 전문이 담긴다** — 개발 PC에선 레포 `data/` 아래라 `.gitignore`·`build_dist._EXCLUDE_PATTERNS`·`verify()`에 올려 두었다. `.db`로 바꾸지 말 것(`stage_data()`가 `data/*.db`를 전부 배포본에 싣는다). 보관은 원고 20개·30일(`prune`, 앱 시작 때).
- **직렬화는 태그 JSON** — 교정 dict에 튜플(`_unify_base`)이 섞여 있어 평범한 JSON은 복원 뒤 타입이 바뀐다. pickle 금지. 표현 못 하는 값이 있으면 저장을 실패로 돌린다(틀리게 복원되는 저장본보다 없는 편이 낫다). 저장 구조를 바꾸면 `review_session.SCHEMA`를 올린다 — 다른 버전은 읽지 않는다.
- **무엇을 저장하나**: `ReviewPanel.export_state()`(교정 목록 + **등장 목록 그대로** + 표기 일관성 기록), 추출 텍스트·쪽수·각주 줄, 분석 옵션, `_consistency_done`, 학습 큐 기록 여부, 원문 활동 로그(`ActivityPanel.export_entries` — 이어서 하면 분석 로그가 당시 시각으로 돌아오고 완료 대시보드 로그도 온전하다). ★등장은 본문에서 다시 찾지 않고 **그대로** 되살린다(`restore_state`) — 다시 만들면 auto/by_user·excluded/shadowed가 처음 상태로 돌아가 부분 결정이 사라진다. 교정 목록 순서가 곧 `ci`라 복원은 다시 정렬하지 않는다. 파생값(교정 상태·skip·겹침 합성)은 `_derive_all`로 다시 계산한다. 복원은 **패널을 건드리기 전에** 등장 위치를 본문과 대조해, 어긋나면 ValueError → 저장본을 지우고 새로 분석하라고 안내한다.
- 표기 일관성 단계 **도중**에 저장되면 그 단계에 들어가기 직전 상태(`_fam_resume`)를 쓴다 — 단계 안의 결정은 '적용' 전엔 교정에 없다. 복원하면 교정 카드 화면으로 돌아오고 푸터가 일관성 검토를 다시 연다.
- **이어서 하기 — 두 입구**: ⓐ 같은 원고로 '교정 분석 시작'을 누르면 AI를 부르기 **전에** `LightConfirmDialog.choose`로 묻는다 — 이어서 검토 / 새로 분석 / Esc=아무것도 안 함(Esc가 새 분석 = AI 재호출로 읽히면 안 된다). 이어서 할 때 분석 옵션은 저장본의 것, **결과물 축(`_OUTPUT_OPTS`)만 지금 고른 값**을 따른다. ⓑ 앱 시작 때 적용하지 않은 가장 최근 저장본이 있고 원고가 그 자리에 그대로면 한 번 묻는다. 같은 저장본으로는 다시 묻지 않는다(`prompted_for` = 그때의 `saved_at`). 그동안 업데이트 모달은 미룬다(`_resume_prompting`).
- **다시 적용** — 완료 화면에서 레일 '검토'를 누르면 화면만 바꾸던 것을 **검토 단계로 되돌린다**(예전엔 단계가 '완료'로 남아 푸터에 초기화만 있었다). 푸터는 '✓ 다시 적용 (N항목)'과 '적용 뒤 바뀐 결정 n곳'(`_decisions_changed`)을 보인다. 레일 '완료'로 다시 적용 없이 돌아갈 수 있다. 다시 적용은 같은 이름 산출물을 덮어쓰고(잠겨 있으면 브리지가 저장 실패를 예외로 낸다), 결과물 추가분은 이전 결정 기준이라고 로그로 알린다.
- **적용은 교정 목록의 깊은 사본을 받는다**(`_applied_corrections`). 적용 뒤에도 카드를 바꿀 수 있게 됐으므로 ① 결과물 추가가 결과 화면과 같은 결정을 쓰고(불변식②) ② 워커 스레드가 도는 동안 카드 클릭이 그 dict를 바꾸지 않게 한다. 완료 대시보드도 그 사본을 그린다.
- **적용 실패·취소는 검토 화면으로**(`_on_apply_error`) — 설정으로 가면 재시도가 '새 분석'뿐이었다. 이전 결과(`self._result`)는 지우지 않는다. 레일 '완료'의 오류 표시는 다음 적용 시작 때 `clear_error`로 거둔다.
- 학습 큐(공유 용어 뇌)는 **한 검토에 한 번만** 적는다(`_events_recorded`, 저장본에도 실린다) — 다시 적용·이어서 하기 뒤의 적용이 같은 결정을 두 번 세지 않게.
- 함께 고친 잠복 결함: `load()`가 표기 일관성 단계 도중 초기화된 그리드를 계열 카드 모드로 남겨 두던 것, 이음매 그룹 캐시(`_jmap`)가 교정 **수**로만 무효화돼 새 문서의 교정 수가 같으면 이전 문서의 그룹을 돌려주던 것(`_reset_document`), 새 분석이 이전 실행의 `self._result`를 비우지 않던 것.

## 결과 화면 (완료 대시보드)

**Result = completion dashboard**: [ui/widgets/result_panel.py](../ui/widgets/result_panel.py) renders a report-style dashboard — header (파일명+완료 시각+수작업 대비 절약 시간 시계) / pipeline hero (01 분석 N자 → 02 교정 제안 사전·규칙/AI 분해 → 03 적용 N건·본문 M곳·적용률, terms: 건=항목·곳=등장) / 상세 분석 (제안 소스 도넛·적용률 게이지·오류 유형 바) / 산출물 카드 / 실패항목(인라인 사유, no dialog) / 교정 진행 로그, all inside a vertical QScrollArea. Numbers are the heroes: `AnimatedNumberLabel` count-up (OutExpo + 착지 팝, final-width reserved so layout doesn't shift; font set via per-instance stylesheet because global QSS `QWidget{font-size:13px}` overrides `setFont`). `show_result(result, log, corrections=, char_count=, file_name=)` — main_window passes the extras at apply-done; a later change to the same run (추가 산출물 완료 등) goes through `update_result(result)`, a **static** re-render that reuses the stored extras and keeps the completion timestamp (result-dict identity), because replaying the whole count-up/chart animation reads as a new run. `refresh_theme()` re-renders statically (no re-animation). Chart widgets read `current_palette()` at paint time; only bundled Lucide icons exist (no pie-chart/clock/file-spreadsheet — use the names in `assets/icons/`, e.g. table/list-checks/clipboard-check). The progress log there is **the same log the activity panel shows** — `ActivityPanel.get_proofreading_log()` returns its already-condensed display rows (`[태그] 내용`), minus HWP-bridge plumbing (`_PLUMBING_KW`, which also catches `err`-level lines that bypass `_DROP`). `result_panel` renders them as-is and only owns the two-column time/text alignment. ⚠ It used to receive raw messages and re-curate them with its own `_curate_result_log`/`_LOG_DROP`/`_LOG_LEAD` rules; two rule sets meant the same run read differently on the two screens and every wording change had to be made twice — that second pass was deleted 2026-07-23. **Change log wording in exactly one place: `activity_panel._RULES`.** There is no settings dialog (the HWP-version-registration `settings_dialog.py` and its header button were removed 2026-06-17; the Gemini API key comes from env/config.ini/embedded org key).
