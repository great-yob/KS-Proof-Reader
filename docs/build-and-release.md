## Building for distribution (build_dist.py)

```powershell
.\.venv64\Scripts\python.exe build_dist.py --clean      # → dist/KS-AI Editor/ (~540MB, v1.8.5)
```

Prerequisites: **Inno Setup 6** (installer) and a **32-bit Python 3.11 with `pywin32` + `pyinstaller`** (HWP bridge). Missing Inno only skips the setup file with a warning; a missing 32-bit Python **fails the build** — see below for why that's deliberate. Useful flags while iterating: `--skip-bridge` (reuse the last 32-bit bridge), `--no-installer`, `--no-zip`.

[build_dist.py](../build_dist.py) (PyInstaller `--onedir`; `--onefile` is forbidden — the 160MB `stdict.db` would be re-extracted to temp on every launch). It:
1. Reads the three API keys from `config.ini`/env, Fernet-encrypts them into a generated `core/_org_keys.py`, bundles it, and **deletes it in a `finally` block** so no plaintext survives in the repo. `core/config_loader.py`'s module-level `_load_org_keys()`/`_decrypt_org_key()` decrypt at runtime.

⚠ **The repo and its releases are PUBLIC, and the decryption key ships in the same file as the ciphertext — so the embedded keys are extractable by anyone.** This was an accepted trade-off (2026-07-22): the three keys are free-tier, read-only, rate-limited and individually revocable (Gemini free tier — no billing attached; 우리말샘/온용어 — free dictionary lookups), and a public repo is what makes the unauthenticated auto-updater work at all. **The rule that follows: only ever embed keys of that character.** Never add a key with billing attached, write access, or access to customer/personal data to `collect_keys()` — route those through a server proxy instead. Rotate the embedded keys if abuse shows up in the quota dashboards.

⚠ **Public repo ⇒ no customer-identifying content may be committed.** `교정샘플/` is gitignored, and measurement tables in `docs/` refer to manuscripts as 실파일A/B/C (same convention as the goldset's `실파일06/24`). Keep it that way when adding new measurements.
2. Excludes secrets/customer data from the bundle (`key.txt`, `config.ini`, `교정샘플/`, `korean-ambiguity-data/`, caches) and verifies afterwards that none leaked — **never add a rule that includes the repo root wholesale**.
3. Excludes `torch`/`transformers`/`tokenizers`/`huggingface_hub` — dead weight from the **removed KoGEC engine**, still present in `.venv64` but imported by nothing (960MB → 485MB). Unexclude only if a verified local model is ever reintroduced.

## 빌드 셸 PATH (2026-10-18)

★**같은 커밋이 빌드한 셸에 따라 다른 번들이 됐다.** PyInstaller는 바이너리 의존성(Qt TLS 플러그인이 찾는 `libssl-3-x64.dll`·`libcrypto-3-x64.dll`)을 PATH에서도 찾는데, Git Bash에서 빌드하면 PATH 앞쪽의 `C:\Program Files\Git\mingw64in`에서 **Git의 OpenSSL**을 집어 `_internal/`에 넣었다(PowerShell로 만든 v1.8.5 릴리스본엔 없다 — 클린 빌드 두 번의 파일 목록을 대조해 찾았다). 앱은 Qt 네트워크를 쓰지 않아 기능 영향은 없었지만 재현성이 깨진다. `_build_env()`가 PyInstaller(64비트 본체·32비트 브리지 둘 다)에 넘기는 PATH에서 Git `mingw64`·`usr`·`bin`과 MSYS 경로를 빼고(`Git\cmd`의 git.exe는 둔다), `verify()`가 `_FOREIGN_DLLS`를 발견하면 빌드를 무효로 본다. 실측 소요(클린 빌드 120초): 키 0.3 · PyInstaller 57 · bridge32 13 · 배치+verify 0.4 · Inno 31 · app.zip 9.6 · data.zip 7.8초.

## 산출물 3종 · 설치 파일(Inno Setup)

**App and data ship separately** — they change at wildly different rates, so one build emits three artifacts into `dist/release/`:

| Artifact | Size | When |
|---|---|---|
| `…-Setup-{ver}.exe` | ~200MB | first install (what users download) |
| `…-{ver}-app.zip` | **~120MB** | code changes (frequent) — updater app channel |
| `…-data-{YYYY.MM}.zip` | ~138MB | dictionary updates (rare) — updater data channel |

(Sizes as of v1.8.5 / data 2026.09 — they drift with every build.)

**The first-install artifact is an Inno Setup installer**, not a zip ([installer/KS-Proof-Reader.iss](../installer/KS-Proof-Reader.iss), compiled by `build_installer()` via `ISCC.exe`; `winget install --id JRSoftware.InnoSetup -e`, discovered through `ISCC_PATH` → known paths → PATH, and **skipped with a warning** rather than failing the build if absent). It installs per-user into `%LOCALAPPDATA%\Programs\KS-AI Editor` with Start-menu/desktop shortcuts and an Add-or-Remove-Programs entry. ⚠ **Per-user is not cosmetic**: Program Files would make the install folder read-only, and `updater.install_app()` replaces that folder wholesale with robocopy — it would die on permissions. `PrivilegesRequired=lowest` also means no UAC prompt. `DisableDirPage=yes` hides the destination-folder page — not just for convenience but to **enforce** that install path, since a user picking Program Files would break auto-update. `AppId` is a fixed GUID — changing it makes Windows treat an upgrade as a second product. `[UninstallDelete]` sweeps `{app}` because files added later by the auto-updater aren't in the uninstall log; uninstall then *asks* before removing `%LOCALAPPDATA%\KS-AI Editor` (settings, cache, updater-installed dictionary data — this path must match `datapaths.APP_DIR_NAME`). The `.iss` must stay **UTF-8 with BOM** or Inno reads it as ANSI and mangles the Korean.
⚠ The installer is **unsigned**, so Windows SmartScreen shows "알 수 없는 게시자" on first run — users must click 추가 정보 → 실행. Signing needs a paid code-signing certificate; the old zip had the same problem, just less visibly.
`full.zip` was retired on 2026-07-22 (the installer replaces it). `updater._pick_asset` still falls back to `-full.zip` when no `-app.zip` exists — harmless, since app releases always carry `app.zip`.

## 데이터 배치 · kiwi 모델

Data (`stdict.db`, `eomun.db`, `userdict.db`, **`kiwipiepy_model/`**) is staged **next to the EXE in `data/`**, never inside `_internal/` — bundling it there would make it unreplaceable. `verify()` fails the build if it finds `_internal/data/stdict.db`. The kiwi model is excluded from PyInstaller (`--exclude-module kiwipiepy_model`) and passed to `Kiwi(model_path=…)` instead; `kiwipiepy` never imports the model package, so this is safe.

⚠ **Never call `Kiwi(model_path=…)` without validating the path first.** A missing or mismatched model raises a catchable Python exception and *then* takes the process down with a native heap corruption (`0xC0000374`) — `try/except` does not save you. `datapaths.kiwi_model_ok()` is the guard: it checks the required model files exist **and** that the model's minor version matches the installed `kiwipiepy` (the model is version-locked to it — lib 0.23.2 ↔ model 0.23.0). `core/morph._get_kiwi()` consults it and, when frozen with no valid model, refuses to construct `Kiwi` at all. A mismatch therefore degrades to "morphology off" (graceful) instead of crashing — but that silently removes lemma restoration, the spacing backstop and the personal-name guard, so `build_dist.verify()` also fails the build on mismatch. **kiwipiepy is a dependency upgrade, not periodic maintenance**: bump it only when worthwhile, gate on `run_goldset.py`, and if the *minor* changes you must ship the data package too.

## 버전 · 업데이터

**Two version numbers, deliberately independent** — top-level [version.py](../version.py): `APP_VERSION` (semver) and `DATA_VERSION` (`YYYY.MM`). The sidebar shows both on two lines. ⚠ The *authoritative* data version is `stdict.db`'s `meta.data_version` via `nikl_dict.data_version()` — `version.py` only records what a build packaged, and data updates independently. UI and updater both prefer the DB value. Release tags: `v1.0.0` (app), `data-2026.07` (data), `stdict-2026.07` (CI's partial DB).

[core/updater.py](../core/updater.py) polls GitHub Releases on both channels. Data installs into `user_dir()/data` (staged → validated → swapped; datapaths ranks it first, so a restart is enough). App updates need a helper `.bat` because a running EXE can't overwrite itself. ⚠⚠ The helper's final `rmdir /S /Q "{tmp}"` must target **only the update's own `mkdtemp` work folder** (`install_app`'s `work`) — it used to receive `staging.parent`, which *is* `%TEMP%`, so every in-app update recursively deleted the user's entire temp folder (other programs' temp/recovery files included; found 2026-10-16 audit, fixed — verified in a sandbox with canary files). `discard_download` likewise removes only a `ksproof-upd-*` folder directly under `gettempdir()`; besides the two installers, `UpdateDialog.reject` calls it for a download the user **deferred** ('나중에'/Esc) — that zip used to stay in `%TEMP%` for good, one 120–138MB copy per deferral (found 2026-10-18). ⚠ **A data install can't swap the folder while the app runs** — `nikl_dict` keeps its DB connection open for the whole process, so from the *second* in-app data update on (user `data/` already exists and is in use) the rename died with `WinError 5`, every time. `install_data` now validates into `data.new`, stamps it with `datapaths._PENDING_READY`, tries the swap, and on `OSError` leaves it pending; `main.py` calls `datapaths.apply_pending_data()` **first thing, before anything opens a DB** (frozen only — in dev `user_dir()` is the repo root). An unstamped `data.new` is a half-extracted leftover and is discarded. ⚠ `data_dir()` picks the candidate with the **highest `meta.data_version`** (ties → user dir first): the old "first that exists" rule let a stale updater-installed copy in the user folder shadow a newer dictionary shipped by a fresh installer, forever and silently. `find_data`/`kiwi_model_dir` search the chosen folder first. ⚠ `install_data` **refuses to run in dev** unless given an explicit `dest` — in dev `user_dir()` is the repo root, so it would clobber `data/` including the 1.8GB exports. Checking is automatic; **installing is never automatic** — a forced restart mid-proofread would destroy the user's work.

### 업데이트 UI 배선

**UI wiring** (added 2026-07-23 — before that `updater.py` was complete but *nothing imported it*, so the app never checked and users saw no update path at all): `MainWindow._start_update_check()` runs [ui/workers/update_worker.py](../ui/workers/update_worker.py) `UpdateCheckWorker` at startup (network I/O off the GUI thread; `core/` stays PySide6-free). A hit shows a persistent accent badge in the sidebar footer (`Sidebar.set_update_available`, clicking emits `update_clicked`) **and** opens [ui/widgets/update_dialog.py](../ui/widgets/update_dialog.py) `UpdateDialog` once per run (`_update_prompted`). The dialog is one window walking three states — 안내 → 진행률 → 재시작 — because swapping windows makes the frameless modal jump; it downloads via `UpdateDownloadWorker` and emits `apply_requested`, and **never installs**: only `MainWindow._on_update_apply` calls `install_app`/`install_data`, since only it knows whether a proofread is running (`_open_update_dialog` refuses during `running`/`apply_running`). `install_app` returning True means the helper `.bat` is already waiting on this PID, so the window **must** then `close()`. It reuses the light-fixed `build_light_card`/`LIGHT_CARD_QSS` surface (no `refresh_theme` — theme-independent by design). ⚠ `_summarize_notes` deliberately hunts for the changelog heading rather than taking the first lines: this repo's release bodies **open with install instructions**, so a naive head-truncation summarized "받아 실행하세요" instead of what changed. ⚠ The check worker has no cancel path (a blocking socket read), so `closeEvent` disconnects it and waits only 800ms before `terminate()` — routing it through `_cleanup_worker` would stall shutdown by 5s on a dead connection. ⚠ The **download** worker can hang the same way (30s socket timeout): `UpdateDialog.reject` (Esc mid-download) waits 3s and, if the read is still blocked, **detaches** the worker (`setParent(None)` + module-level `_ORPHANS`) instead of letting `dlg.deleteLater()` destroy a running QThread — that used to kill the whole app (`0xC0000409`, reproduced 2026-10-18). A download that finishes after the dialog closed is discarded (`_discard_late`), and `closeEvent` calls `update_dialog.stop_orphan_downloads()` (short wait → `terminate`).

## 데이터 경로 (datapaths)

⚠ **Every data-package DB must resolve through `datapaths`** — `eomun_rules` and `userdict` used to hard-code `_MEIPASS/data` + EXE-side only, so an in-app data update (installed in the user folder) never reached them. `eomun.db` now uses `find_data`; `userdict.db` picks the **highest `meta.snapshot_ver`** among the sync build (`datapaths.userdict_runtime_path()` = `cache_dir()` when frozen) and the data-package copies, and `userdict.reload()` (called by `userdict_sync.pull`) switches to a fresh build without a restart. `build_userdict_db` takes both its write path and its **homograph-guard `stdict.db`** from `datapaths` — when frozen its `Path(__file__).parent/"data"` is `_internal/data`, where `stdict.db` does not exist, so guards 2·3 were silently off in every shipped build (the warning print goes nowhere in a windowed app).

**Path resolution is centralized in [datapaths.py](../datapaths.py)** — a deliberately dependency-free top-level module (importing `core` would drag in `google.genai` and the HWP bridge just to look up a word). It resolves data as user dir → EXE-side → bundle, so an updater-installed copy wins. Anything written at runtime goes to `cache_dir()` (`%LOCALAPPDATA%\KS-AI Editor` when frozen) — the install folder and `_internal/` can be read-only. ⚠ Two runtime files are still **exceptions**, written next to the EXE (`data/event_queue.db` — `event_queue._resolve_db_path`; `data/.ks_session` — `auth._session_path`): it works because the install is per-user and writable, and app updates' `robocopy /E /MOVE` leaves them alone, but uninstall sweeps them and a read-only install would silently disable both. Moving them needs a migration of existing users' queue/session (found 2026-10-18, not yet changed). `ConfigLoader._save()` swallows `OSError` so a read-only install degrades to "settings don't persist" instead of crashing the theme toggle; when frozen, `config.ini` is **read** from both the EXE folder (deployer override) and the user folder, but **written** only to the user folder.
