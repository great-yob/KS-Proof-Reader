## Engine pipeline (v5)

Defined in [ui/workers/proofreading_worker.py](../ui/workers/proofreading_worker.py), executed on a `QThread`:

1. **Extract** — `HwpEditor.open()` → `get_text()` (via the bridge/backend — [hwp-bridge.md](hwp-bridge.md)).
2. **Local Dictionary Screening (1st Pass)** — `KoreanDictValidator` (top-level [nikl_dict.py](../nikl_dict.py), *not* under `core/`) queries `data/stdict.db` to extract suspicious words (unregistered words, neologisms, dialects). [core/morph.py](../core/morph.py) uses kiwipiepy to restore inflected surface forms to their dictionary lemma so genuine conjugations aren't flagged as unregistered (graceful no-op if kiwipiepy is missing). Two **cached online fallbacks** then prune false "미등재" flags, in order: [nikl_api.py](../nikl_api.py) (우리말샘, serial — its lock spans the network call) → [onterm_api.py](../onterm_api.py) (**온용어**, 국립국어원 전문용어 120만, parallel `ThreadPoolExecutor(4)`). Both gate on `is_likely_typo` and cache permanently in `data/api_cache.db` (separate tables `cache` / `onterm_cache` — never merge them). ⚠ 우리말샘 answers an invalid/revoked key with **HTTP 200 + a root `<error>` XML even for `req_type=json`**; the old parser read that as total 0 and **permanently cached every queried word as 미등재** (a key rotation would poison every user's cache). `nikl_api._parse_response` now returns a number only when the result shape (`channel.total` / `<total>`) is confirmed — `(None, [])` = 확인 불가 (not cached) vs `(0, [])` = 미등재 확정 (cached) must never blur — an error response disables lookups for the run (`last_error()`, logged by worker [2]), and `_migrate_cache` (`nikl_cache_meta.cache_ver`) purged the old `found=0` rows once. ⚠ 온용어 contains non-standard spellings, so `is_registered_onterm` carries a **norm_map/spelling_pairs veto guard** (`_norm_pair_components`) — see [docs/onterm-integration-design.md](onterm-integration-design.md).
3. **Gemini AI** — generation is built via [core/correction_engine.py](../core/correction_engine.py) `build_engine()` → `GeminiEngine`, a thin adapter over [core/gemini_checker.py](../core/gemini_checker.py) `GeminiChecker` (the role-separation seam — generation is the swappable part). It uses a 30-year expert persona ([core/prompts.py](../core/prompts.py)) plus the local dictionary context. API calls are chunked (`AI_CHUNK_TYPO=15000`, `AI_CHUNK_POLISH=8000`) and throttled (`AI_CALL_DELAY=4.1s`) for the 15 RPM free tier. ⚠ **Do not reach for `AI_CHUNK_TYPO` as a recall lever — that was measured and rejected (2026-07-27).** A full-document sweep of 8 sizes appeared to favour 6,000, but a control that held the size fixed and merely *shifted the boundaries by half a chunk* changed ~80% of the output (6,000: 84%/29% → 61%/20% precision/recall; 15,000: 92%/20% → 76%/24%). **Boundary placement, not size, dominates**, so the sweep really measured eight boundary configurations and the size ranking is close to accidental. ⚠ **A smarter chunker is not the way out either — measured and closed 2026-07-28 (do not retry).** A (chunker × size × phase) grid on real Gemini — current chunker, paragraph-preserving, and a structure-pinned chunker (no block/table cuts, headings aligned) — never beat 26% phase-pair Jaccard, and pinning to structure made it *worse*: the culprit is splitting the document at all, not where the cuts land. The only variable that correlates is the **number of chunks** (fewer = steadier), which is why 15,000 stays. The remaining levers are outside chunking (prompt attention / review-card exposure). Full tables and the RPD budget are in the comment above the constant in `core/models.py`. Model: `gemini-3.5-flash-lite`, with an automatic fallback chain (`_MODEL_CANDIDATES` in `gemini_checker.py`) ordered by **free-tier RPD** — `3.5-flash-lite` (15 RPM/500 RPD) → `3.1-flash-lite` (15/500) → `3.5-flash` (5/20; last resort). `2.5-flash-lite` was dropped 2026-08-04 — at 20 RPD it cannot carry a multi-chunk document. The chain advances on three distinct triggers: model unavailable (404/deprecated/permission), **quota exhaustion**, and **transient errors** (5xx/timeout — a model-level 503 used to `break` out and leave the healthy candidates untried; transient switches never block the model) — `_is_quota_error` (narrower than `_is_transient_error`, so 5xx/timeouts don't burn a model) switches **immediately, with no backoff**, since free-tier quota is per-model. ⚠ Only a **daily** 429 (`quotaId …PerDay…`, `_is_daily_quota`) adds the model to `self._quota_blocked` (skipped for the rest of the process). A per-minute or unclassified 429 switches to the next model **without blocking and without unlocking** `_model_id`, so the next chunk asks the preferred model again; if every candidate is minute-limited, the backoff waits at least the server's `retryDelay` (capped at `_RPM_WAIT_CAP`). Treating RPM as RPD (the old behaviour) dropped the 500-RPD model for the whole run after a burst of chunks and could pin the run to 3.5-flash (20 RPD). Only when every candidate is exhausted does it fall through to `_RETRY_DELAYS` backoff.
4. **Merge** — `CorrectionMerger.merge()` deduplicates and sorts suggestions.
5. **Consistency post-pass** — [core/consistency_pass.py](../core/consistency_pass.py) `enforce_consistency()` unifies AI per-chunk nondeterminism: Case A (조사 변형, high confidence) and Case 4 (부분 매칭 전파, low confidence, dictionary-guarded). `reconcile_variant_confidence()` follows. ⚠ The old Case B (edit-distance-1 whole-word substitution) is permanently removed — see file header. ⚠ **The corrected form's stem must not come from an isolated kiwi parse** (fixed 2026-10-19): kiwi reads a bare corrected noun like '배지' as 배/NNG + 이/VCP + 지/EC, so a bare AI correction '뱃지'→'배지' made Case A turn the variant '뱃지를' into **'배를'** (high, a syllable deleted) and Case 4 turn '뱃지만들기' into '배만들기'. 338 of the 12.8K norm_map pairs have that shape. `_canonical_base_correction` now keeps the whole corrected form when the original read as one word but the corrected stem came out shorter, or when the corrected form is itself a headword; josa-appending corrections ('분야'→'분야를') still strip as before. This stage only runs on AI output, so it had **no goldset lock** until Phase D-8 was added.
   - **Card order is deterministic** (2026-10-19): the deterministic layers used to iterate a `set` of document runs ([5.6]/[5.7]/[5.8] and Case A/4 here), so the *order* of otherwise identical cards changed per process (measured: 11 of 20 manuscripts). They now iterate first-appearance order (`dict.fromkeys`); same input → byte-identical output across hash seeds.
6. **Dictionary Re-validation (3rd Pass)** — The AI's suggestions are cross-checked against the local DB. Non-standard terms are assigned `confidence="low"`.
6.5. **Junction coherence pass** — [core/junction_pass.py](../core/junction_pass.py) `resolve()` (worker step `[9.2]`) fixes nested words deciding the *same* spacing junction in opposite directions ('수당수급자'→'수당 수급자' vs '수당수급자확인서'→'수당수급자 확인서'). Measured on 4 reports: 22 conflicts, **20 involving an auto-applied card** — i.e. the split happened without the user ever seeing a card. ⚠ **Automatic resolution is provably impossible**: half the conflicts are legitimate distinctions (한글 맞춤법 제49·50항 allow joined 고유명사/전문용어 — '출산 전후' 44:4 vs '출산전후휴가' 3:1, a 고용보험법 term), and neither the dictionary (출산전후휴가·서비스판매종사자·아파트매매가격지수 are all unregistered) nor frequency aggregation (출산|전후 is 45:7 spaced, which would wreck 출산전후휴가) can tell them apart. So the pass applies a **precedence hierarchy — a word's own document-wide majority beats the junction's, which beats the 규범 default** — and splits conflicts three ways: both sides clear ⇒ *legitimate distinction, untouched*; one side clear and the other has **no** evidence ⇒ auto-harmonized; otherwise ⇒ `Correction.junction_group` + demoted to `low` for the user to decide once. It also recovers cards the binary-split finder structurally cannot see (`find_compound_spacing_consistency` splits a word at exactly **one** point, so '기초연금 수급자 확인서' at 9:1 produced no card at all). ⚠ Invariants: `original` is **never** modified (the document string must stay findable — that's what makes "search for a string that isn't in the file" structurally impossible), letters never change (spaces only), and the 미탐 recovery only ever **splits a joined run** — joining a spaced phrase is the banned 294-noise class. Full rationale in the module header and the `junction-spacing-coherence` memory.
7. **Apply** — `ApplyWorker` sends accepted corrections back through the bridge, and `output/errata_generator.py` emits an Excel errata file.

## 사용자 첨부 사전 — 모든 계층보다 위

**사용자 첨부 사전은 이 파이프라인 전체보다 위에 있다** ([core/user_dict_file.py](../core/user_dict_file.py), 2026-09-03 사용자 지시). 설정 화면 우측 첨부 칸 아래쪽(`SetupPanel`이 아니라 `AttachPanel`의 `DictPanel`)에 2단 엑셀(**A열 원문 · B열 교정문**)을 첨부하면 `options["user_dict_path"]`로 실려 두 가지가 동시에 켜진다: ① 그 목록이 그대로 교정 카드가 되고, ② **다른 어떤 계층도 그 낱말을 고치지 못한다.** 첨부가 없으면 `udict is None`이라 계층이 통째로 잠들어 기존 동작이 한 글자도 달라지지 않는다 — 이게 "엑셀 없으면 기존 로직 그대로"의 구현이다. ⚠ 이름이 비슷한 [core/userdict.py](../core/userdict.py)(서버에서 내려받는 **조직 공유 학습 사전** userdict.db, 워커 [5.6])와 **다른 것**이다. 우선순위는 사용자 첨부 > 국가 표준·사내 페어 > 나머지.
워커 진입점은 넷이고 각각 이유가 있다: **[1.5]** 추출 직후 로드(스크리닝보다 앞) · **[2.5]** `suspicious_words`에서 보호 낱말 제거(이 목록이 AI 프롬프트 컨텍스트 겸 안전망 카드 씨앗이라, 남겨 두면 AI에게 "이 낱말 미등재"라고 일러 주는 셈) · **[4.6]** 카드 주입 + 같은 `original`을 다르게 고치려던 카드 대체 · **[9.7]** 직렬화 직전 **마지막 관문**. ★[9.7]이 진짜 보증이다 — [4.6] 이후에도 [5.6]~[9.6]이 계속 카드를 만들기 때문에, 계층마다 검사를 심는 방식은 새 계층이 생길 때마다 빠뜨린다. 판정식(`violates`)이 한 곳뿐이라 두 번 불러도 어긋나지 않는다.
**엑셀 한 행의 뜻은 앞뒤 공백이 가른다** — 판정은 `classify_row` 하나뿐: 교정문이 비었거나 원문과 완전히 같으면 **보호 전용**(고치지 말 것) · 앞뒤 공백을 떼고도 **글자가 다르면 낱말 페어**(가나문화시→가나문화사, 부분문자열 치환) · 앞뒤 공백을 떼면 **글자가 같으면**(공백만 다름) **경계 규칙**(띄어쓰기 통일 — `' 기술'→'기술'`은 `xx 기술`·`xx기술` 혼재를 `xx기술`로, `'정보 '→'정보'`는 `정보 xx`·`정보xx`를 `정보xx`로). ⚠ 그래서 로더는 셀 값을 **`strip()` 하지 않는다**. `'가나문화시 '`처럼 엑셀에서 딸려 온 우연한 공백은 글자가 다르므로 낱말 페어로 떨어져 무해하다 — 경계 규칙이 되려면 양쪽 글자가 완전히 같아야 한다.
★**경계 규칙은 어절 쌍으로 펼쳐서 카드를 만든다.** `' 기술'`을 그대로 `original`로 쓰면 카드가 "원본 기술 / 교정 기술"로 보여 **차이가 눈에 안 보이고**, 정오표·메모·PDF도 같은 꼴이 되며 인라인 편집은 공백 의미를 잃는다. 그래서 문서에서 매칭된 자리를 양옆 어절까지 넓혀 `'정보 기술을'→'정보기술을'`로 펼친다(한 어절 무리에 규칙이 여럿 걸리면 **한 번에 모아** — '정보 통신 기술'+두 규칙 ⇒ '정보통신기술' 한 장). ⚠⚠ **문자열 그대로 적용하면 안 된다 — 실측으로 확인**(2026-09-03 · 실파일H · 규칙 2개): 가드 없이는 174곳이 나오는데 '한다. 기술'·'정책, 기술'·'하는 기술을'·'및 기술과'·'각 기술'처럼 **명백히 틀린 자리가 절반을 넘었다**. 전부 수락 상태로 뜨므로 사용자가 100장을 거절해야 한다. 그래서 `core/morph.is_joinable_left`/`is_joinable_right`로 양옆 어절을 거른다 → 90곳. ⚠ **앞말과 뒷말의 기준이 다르다**: 조사는 복합어 전체에 붙으므로 앞말에 조사가 있으면 별개 구(句)라는 증거라 불가, 뒷말의 조사는 정상이라 가능 — 이 비대칭을 놓치면 '인공지능 기술의'처럼 **맞는 자리가 통째로 막힌다**(실측). kiwi가 없으면 **붙이지 않는다**(조용한 오적용보다 조용한 미적용). ⚠ 반대 방향(`'기술'→'기술 '`, 붙은 것을 띄운다)에는 `is_word_split_point` — **형태소 경계에서만** 띄운다. 없으면 '기술이'가 '기술 이'로 쪼개진다(실측).
보호 판정은 **문자열 규칙**이다: 보호 낱말 t가 원문에 있을 때 교정문에도 t가 그대로 있으면 허용(주변만 손댄 교정 — '콘텐츠개발'→'콘텐츠 개발'), 사용자가 정한 결과 u가 있으면 허용(겹침 합성 결과 — '리플렛등'→'리플릿 등'), 둘 다 아니면 드롭('가나문화사'→'가나 문화사'). 원문==교정문(검수 필요 카드)도 드롭 — 사용자가 이미 답을 적어 둔 낱말이다. ⚠ **1글자 표제어는 보호에서 제외**한다(교정은 한다): 부분문자열 보호라 '사' 하나로 문서 절반의 교정이 죽는다. ⚠ 교정문 칸이 비면 **보호 전용**(고치지 말 것)이 되고, 표제어 검색은 어절이 아니라 **부분문자열**이다(사용자는 '가나깅'만 적지 '가나깅은'까지 적지 않는다 — 부분문자열이면 조사형이 저절로 맞고 브리지 `RepeatFind` 좌표계와도 같다). ⚠ 경계 규칙의 **낱말 토큰**('기술'·'정보')은 보호 집합에 넣지 않는다 — 흔한 명사를 부분문자열로 보호하면 '기술울' 같은 오탈자 검수 카드까지 조용히 사라진다. 경계 보호는 ① 펼쳐 낸 어절 쌍을 보호에 등록하고 ② 다른 계층 교정의 **교정문에 경계 규칙을 적용해 어긋나면 맞춰 고쳐 준다**(`harmonize`) — 드롭이 아니라 조율인 이유는, 드롭하면 '그는 긔술을'→'그는 기술을' 같은 **오탈자 교정까지 함께 잃기** 때문이다. 조율 결과가 원문 그대로면(= 사전 결정을 되돌리기만 하는 교정) 그때는 드롭한다.
카드는 `source="user_dict"` · `category="사용자 사전"` · `reason="사용자 사전에 등록된 항목"`(문구 고정) · `confidence="high"`이며, 직렬화에서 **`status="accepted"`로 나간다** — 검수 화면에 수락된 상태로 등장한다. 거절·직접수정·재수락은 일반 카드와 같은 경로다. ⚠ 단 `_build_occurrences`가 이 카드만 `auto=False`로 둔다: `auto=True`면 거절할 때마다 "반복 항목을 반대로 처리할까요?" 팝업이 끼어드는데, 수락 상태로 뜬 이유가 반복 전파가 아니라 사용자의 사전이기 때문이다. `nikl_dict.validate`도 이 source를 건너뛴다(low로 떨어지면 `_needs_review`가 '검수 필요' 배지를 달아, 이미 답한 것을 되묻는 카드가 된다). `event_queue._SKIP_SOURCES`에도 들어 있다 — 개인 목록이지 조직 합의가 아니고, 사람 판단이 실린 적 없는 accepted가 학습 큐에 쏟아진다.
⚠ **AI 프롬프트는 건드리지 않는다.** 보호는 전부 결정론 후처리다 — 프롬프트는 내용뿐 아니라 순서 변경만으로 정밀도가 88→75%로 무너졌고(memory `gemini-call-hardening-and-prompts`), 글로서리 지침은 반복 표기 문서에서 504 폭주를 낸 전력이 있다(`glossary-runaway-504`). [2.5]는 지침을 더하는 게 아니라 목록에서 빼는 것이다.
